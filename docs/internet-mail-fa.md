# فعال‌سازی پروتکل‌های ایمیل — ۲۰۲۶-۱۰-۲۷

این گزارش وضعیت جدیدتر از گزارش اولیهٔ `three-domains-fa.md` را ثبت می‌کند.
ارسال و دریافت خارجی هنوز به علت محدودیت اتصال TCP 25 و PTR تکمیل نشده است.

## انجام‌شده

- DNS مستقیم هر سه `mx.*` برابر `37.152.182.250` است و MX هر دامنه به نام
  `mx` همان دامنه اشاره دارد. شش کلید عمومی DKIM با دادهٔ سرویس مطابقت دارند.
- Nginx فایل `deploy/nginx-mx.conf` فقط HTTP-01 را روی نام‌های مستقیم سرو می‌کند؛
  سایر مسیرهای HTTP این نام‌ها پاسخ ۴۰۴ دارند. مسیرهای وب‌میل تغییر نکرده‌اند.
- گواهی Let's Encrypt با SAN هر سه `mx.*` در lineage به نام `webmail-mx`
  صادر شد؛ اعتبار تا ۲۰۲۷-۰۱-۲۵ است. کلید خصوصی در سرور باقی می‌ماند.
- `scripts/configure-mail-tls.py` گواهی را از فایل‌های محافظت‌شده وارد Stalwart
  می‌کند و مقدار پیش‌فرض hostname ایمیل را `mx.amirhossein-danesh.ir` قرار می‌دهد.
  `STALWART_PUBLIC_URL` همچنان `https://mail.amirhossein-danesh.ir` است؛ OAuth و
  JMAP وب‌میل همان آدرس اصلی را حفظ می‌کنند.
- SMTP ورودی روی ۲۵، ارسال کاربر روی ۴۶۵ با TLS و ۵۸۷ با STARTTLS، و IMAP
  روی ۹۹۳ منتشر شده‌اند. سرویس‌های POP3 و ManageSieve که پورت عمومی ندارند
  در تبلیغات سرویس‌ها حذف شدند.
- ارسال کاربر نیاز به احراز هویت دارد؛ آدرس فرستنده باید متعلق به حساب باشد؛
  relay بدون احراز هویت غیرفعال است.
- Certbot timer فعال است و deploy hook از `deploy/renew-mail-certificate.sh`
  در `/etc/letsencrypt/renewal-hooks/deploy/webmail-service` نصب شده است.
  اجرای hook روی گواهی واقعی با موفقیت انجام شد؛ dry-run تمدید ACME اجرا نشد.

## آزمون‌های انجام‌شده

- از سیستم خارجی، هر سه نام روی پورت‌های ۴۶۵، ۵۸۷ و ۹۹۳ با گواهی معتبر
  TLS 1.3 ارتباط برقرار کردند. SMTP بدون احراز هویت، ارسال را نپذیرفت.
- برای هر سه حساب، ورود SMTP/STARTTLS و IMAP/TLS موفق بود؛ پیام آزمایشی
  به همان حساب ارسال، از صندوق خوانده و پس از بررسی حذف شد. هر پیام دو
  امضای DKIM داشت؛ این آزمون، تحویل به Gmail یا اعتبارسنجی امضا توسط آن نیست.
- روی پورت ۲۵ از خود سرور، ارسال به مقصد خارجی بدون احراز هویت با کد ۵۵۰
  رد شد. روی ۵۸۷ ارسال بدون احراز هویت رد شد؛ تلاش حساب احرازشده برای آدرس
  فرستندهٔ غیرمتعلق نیز رد شد. هیچ پیام آزمایشی به شخص ثالث ارسال نشد.
- شش آزمون مخزن، اعتبار Compose، سلامت کانتینر و `nginx -t` موفق بودند؛
  پاسخ سایت‌های اصلی با خط مبنا یکسان ماند.

## مانع خارج از تنظیمات برنامه

در آزمون IPv4، اتصال خروجی سرور به TCP 25 گوگل و مایکروسافت timeout شد؛
در همان زمان اتصال به گوگل روی ۵۸۷ و ACME روی ۴۴۳ برقرار بود. اتصال سیستم
خارجی به ۲۵ این سرور نیز timeout شد، در حالی که ۴۶۵/۵۸۷/۹۹۳ قابل دسترسی بودند.
listener پورت ۲۵ روی سرور فعال است؛ UFW غیرفعال، OUTPUT برابر ACCEPT و قواعد
Docker برای انتشار پورت برقرارند. این شواهد علت نهایی مسدودی را ثابت نمی‌کنند؛
بررسی فایروال ابری، سیاست SMTP ارائه‌دهنده و مسیر شبکه لازم است.

PTR قبلی نام عمومی معتبر متناظر با سرویس نبود. از ارائه‌دهنده باید درخواست شود:

```text
برای سرور با IP عمومی 37.152.182.250:
۱. محدودیت TCP پورت 25 را در هر دو جهت ورودی و خروجی بررسی و رفع کنید.
۲. PTR / Reverse DNS این IP را روی mx.amirhossein-danesh.ir تنظیم کنید.
```

این یک PTR برای میزبانی هر سه دامنه کافی است؛ رکورد A آن نام باید به همین IP
برگردد. افزودن TXT یا PTR در zone معمولی دامنه جایگزین تنظیم Reverse DNS
در پنل صاحب IP نیست. پس از رفع مانع، آزمون ورودی/خروجی از شبکهٔ مستقل و
ارسال/دریافت با یک صندوق خارجی تحت کنترل مالک هنوز لازم است.

## استقرار و نگهداری

```bash
cd /opt/webmail-service
git pull --ff-only origin main
python3 scripts/configure-mail-tls.py
docker compose -f compose.yaml -f compose.public.yaml up -d --no-build
```

برای بروزرسانی تصویر نیز باید همان دو فایل Compose استفاده شوند. اجرای
`docker compose up -d` بدون override عمومی می‌تواند پورت‌های ایمیل را حذف کند.
فایل‌های Nginx در `deploy/` منبع نسخه‌بندی‌شدهٔ تنظیمات هستند.

پیش از تغییر، هر دو volume در
`/root/webmail-backup-20261027T191326Z/stalwart-volumes.tar.gz` پشتیبان گرفته شدند؛
فهرست آرشیو و SHA-256 ثبت شد. آزمون بازیابی کامل انجام نشد. برای قطع فوری
دسترسی عمومی پروتکل‌ها بدون حذف اطلاعات، دستور `docker compose -f compose.yaml up -d
--no-build` را در همین مسیر اجرا کنید؛ وب‌میل loopback باقی می‌ماند. بازیابی
volume فقط پس از توقف سرویس و حفظ داده‌های جدید مجاز است.
