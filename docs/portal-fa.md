# پرتال خصوصی کاربران ایمیل

ثبت‌نام عمومی وجود ندارد. فقط ادمین حساب اصلی می‌سازد یا دعوت می‌دهد.
این حساب مستقل از حساب‌های Stalwart است. کاربر پس از ورود، صندوق‌های موجود
روی سه دامنه را با رمز معتبر همان صندوق متصل می‌کند. رمزهای اتصال با Fernet
و کلید خارج از دیتابیس رمزنگاری می‌شوند؛ سرویس پرتال رمز مدیریت Stalwart را ندارد.

ایمیل‌ها و پوشه‌ها در Stalwart می‌مانند. پرتال فقط اطلاعات مالکیت اتصال،
رمز اتصال رمزنگاری‌شده و وضعیت درخواست ارسال را نگه می‌دارد. قطع اتصال صندوق
از پرتال، صندوق یا پیام‌هایش را حذف نمی‌کند. پیام‌های پیش از ورود کاربر هم
از همان صندوق خوانده می‌شوند. ساخت آدرس جدید فقط در پنل مدیریت Stalwart است.

## آدرس‌ها

- `https://mail.amirhossein-danesh.ir/` و `https://mail.kappaut.ir/` و `https://mail.unilrn.ir/`: پرتال مشترک کاربران. به‌دلیل جداسازی امن کوکی هر hostname، ورود مرورگر در هر نام مستقل است؛ حساب‌ها و اتصال‌ها مشترک‌اند.
- `/webmail/` روی هر نام: Bulwark موجود برای قابلیت‌های پیشرفته؛ ورود مستقیم صندوق مستقل است.
- `https://mail-admin.amirhossein-danesh.ir/`: صفحهٔ مدیریت.
- `/manage/` روی نام ادمین: ساخت حساب اصلی و صدور لینک تعیین رمز.
- `/admin/` روی نام ادمین: پنل Stalwart برای تعریف صندوق روی هر سه دامنه؛ ابتدا ورود staff پرتال و سپس ورود مدیریتی Stalwart لازم است. `/admin` روی نام‌های کاربران همچنان مسدود است.

فعال‌بودن عمومی نام‌ها مستلزم DNS و HTTPS است؛ وجود فایل Nginx تأیید دسترسی عمومی نیست.
سه رکورد A موردنیاز: `mail` در کاپا و یونی‌لرن و `mail-admin` در دامنهٔ شخصی، مقصد `37.152.182.250`.
رکورد MX جداست و با این رکوردهای وب جایگزین نمی‌شود.

## قابلیت‌ها و حدود فعلی

پرتال Inbox، Sent، Junk و Trash، صفحه‌بندی، نمایش متن امن پیام، دریافت پیوست و
ارسال متن با یک پیوست تا ۱۰ مگابایت دارد. پیام بیش از ۲۰ مگابایت و نمایش HTML
به وب‌میل کامل ارجاع داده می‌شوند. فایل دریافتی فقط attachment است؛ HTML ایمیل
در پرتال اجرا نمی‌شود و تصویر رهگیری خارجی بارگذاری نمی‌شود. خواندن با BODY.PEEK
است؛ مدیریت خوانده‌شدن، جست‌وجوی پیشرفته، حذف و جابه‌جایی در Bulwark موجود است.

کلید فرم ارسال از ارسال دوبارهٔ همان فرم جلوگیری می‌کند. در timeout مبهم،
ارسال خودکار تکرار نمی‌شود. پذیرش SMTP به‌معنی تحویل نهایی یا Inbox نیست.
نسخهٔ Sent پس از پذیرش SMTP جدا ذخیره می‌شود؛ شکست آن به کاربر اعلام می‌شود.

## استقرار

Python 3.12+ و یک venv مستقل لازم است؛ کانتینر Stalwart بازسازی نمی‌شود.

```bash
cd /opt/webmail-service
git pull --ff-only origin main
python3 -m venv /opt/webmail-portal-venv
/opt/webmail-portal-venv/bin/python portal/fetch_wheels.py /root/webmail-portal-wheels
/opt/webmail-portal-venv/bin/pip install --no-index --find-links /root/webmail-portal-wheels -r portal/requirements.txt
/opt/webmail-portal-venv/bin/python portal/run_tests.py
python3 scripts/deploy-portal.py
```

اسکریپت از تنظیمات فعلی و SQLite موجود بکاپ می‌گیرد؛ محیط امن تولید، کاربر
سیستمی محدود و سرویس loopback روی 8091 را می‌سازد. مشخصات ادمین اولیه فقط
در `/root/webmail-portal-admin-credentials.json` است و چاپ نمی‌شود.
برای فعال‌سازی proxy پس از بررسی واقعی، `python3 scripts/deploy-portal.py --install-proxy`
اجرا شود. Nginx موجود تست و reload می‌شود؛ سرویس ایمیل restart نمی‌شود.
قالب فعلی مانند زیرساخت قبلی برای Arvan HTTPS edge با origin HTTP است.
برای رکورد DNS-only ابتدا گواهی معتبر روی origin و server block پورت ۴۴۳
لازم است؛ صرف ساخت رکورد A، HTTPS مستقیم را فعال نمی‌کند. برای پایان‌دادن
HTTP میان CDN و origin، گواهی origin و حالت HTTPS معتبر در پنل آروان لازم است.

محیط محرمانه: `/etc/webmail-portal/portal.env` با مالک `root:webmail-portal` و mode 0640.
دیتابیس: `/var/lib/webmail-portal/portal.sqlite3` با mode 0600؛ هر دو باید با هم
در بکاپ محافظت‌شده حفظ شوند. از دست‌رفتن کلید، اتصال‌های ذخیره‌شده را غیرقابل
بازیابی می‌کند؛ خود پیام‌های Stalwart مستقل‌اند. `DEBUG=False`، CSRF، کوکی امن
host-only، CSP، جداسازی مالکیت و محدودیت تلاش ورود فعال‌اند. محدودیت مبتنی بر
آدرس proxy و نام کاربر است؛ برای شمارش دقیق IP کاربر پشت CDN باید trusted
real-IP ranges رسمی آروان جدا تنظیم شوند. MFA ادمین پرتال هنوز پیاده نشده است.

## گردش کار ادمین

۱. در پنل Stalwart، Management → Directory → Accounts، صندوق و دامنهٔ صحیح را بسازید؛ حساب موجود را بازنویسی نکنید.
۲. در `/manage/auth/user/` حساب اصلی کاربر را بسازید. کاربران عادی نباید Staff یا Superuser باشند.
۳. در فهرست کاربران، عمل «نمایش لینک دعوت / تعیین رمز» را اجرا و لینک خصوصی را فقط به همان شخص تحویل دهید. اعتبار ۲۴ ساعت است؛ با تعیین رمز باطل می‌شود. ایمیل دعوت خودکار ارسال نمی‌شود.
۴. مشخصات صندوق را امن تحویل دهید؛ کاربر پس از تعیین رمز اصلی، آن را در «اتصال صندوق موجود» اضافه می‌کند. رمز اختصاصی برنامه ترجیح دارد.

## آزمون و rollback

`python portal/run_tests.py` آزمون جدا از Production با دیتابیس موقت است.
موفقیت آن فقط Mock/کد است؛ اتصال واقعی IMAP/SMTP، مرورگر و DNS/TLS جدا بررسی شوند.
در برگشت، تنظیم Nginx پوشهٔ `/root/webmail-portal-backup-TIMESTAMP` را ابتدا
بازبینی و برگردانید، `nginx -t` و reload کنید. سپس فقط سرویس `webmail-portal`
را در صورت نیاز متوقف کنید. داده‌های پرتال را نگه دارید؛ دیتابیس/volumeهای
Stalwart، MX، SMTP و وب‌میل قبلی نیاز به حذف یا بازیابی ندارند.
